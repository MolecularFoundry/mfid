# Changelog

All notable changes to MFID will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] — 2026-09-10

Major release: MFID now generates its UUIDv7 identifiers according to the ratified
[RFC 9562 §5.7](https://datatracker.ietf.org/doc/html/rfc9562.html#section-5.7)
(Method 3) with a self-contained implementation. See the
[MFID v1 vs v2](README.md#mfid-v1-vs-v2) section of the README for the
full comparison.

### Breaking changes

- **UUIDv7 bit layout changed** from the pre-RFC IETF draft to RFC 9562 Method 3.
  MFIDs produced by v2 have a different byte layout from those produced by v1:
  a 48-bit millisecond timestamp, a 12-bit sub-ms fraction in `rand_a`, and 62
  random bits in `rand_b`.
- **Cross-version sort behavior:** v1 and v2 MFIDs generated at the same
  wall-clock instant no longer sort adjacently. v2 MFIDs sort *before* v1
  MFIDs of the same instant because v2's wider timestamp field carries more
  leading zero bits.
- **`mfid.timestamp_ns()` is v2-only.** It must not be applied to MFIDs
  generated by v1, as the bit interpretation differs.

Existing v1 MFIDs remain valid RFC 4122 UUIDs and still sort in creation order
relative to each other.

### Added

- `mfid.uuid7()` — self-contained RFC 9562 §5.7 Method 3 UUIDv7 generator.
  Guarantees strict per-process monotonicity via a minimum sub-ms quantum
  advance (~245 ns) per call, so successive IDs remain distinguishable even
  under bursts that outpace the wall clock or on platforms with coarse
  `time.time_ns()` resolution (Windows without `GetSystemTimePreciseAsFileTime`,
  macOS `gettimeofday`, WASM/Pyodide, etc.).
- `mfid.timestamp_ns(u)` — recover the generation time (nanoseconds since
  Unix epoch) from an MFID's UUID object. Resolution ~244 ns.
- Optional `ns=` parameter on `mfid.mfid()`, `mfid.uuid7()`, and
  `mfid.cb32_uuid7()` for deterministic, testable output. The explicit-`ns`
  path bypasses the monotonicity guard so callers get reproducible results.
- "Coarse-clock or tight-burst worst case" example in the README demonstrating
  the min-advance guarantee.
- "Annotated example" section in the README mapping each Crockford Base32
  character to the underlying UUID bits.
- "MFID v1 vs v2" section in the README covering bit layout differences,
  sort behavior across versions, and migration notes.

### Removed

- Runtime dependency on the `uuid7` PyPI package (`uuid_extensions`). MFID v2
  has **no runtime dependencies**.

### Packaging

- Migrated from `setup.py` to PEP 621 `pyproject.toml`.
- Switched build backend from `setuptools` to `flit_core` (smaller, faster,
  zero configuration required for single-module pure-Python projects).
- License now declared with the PEP 639 SPDX identifier (`BSD-3-Clause`).

## [1.0.0] — 2025-02-05

Initial published release.

### Added

- `mfid.mfid()` — generate a 26-character Crockford Base32 MFID backed by
  a UUIDv7 from the [`uuid7`](https://pypi.org/project/uuid7/) package.
- `mfid.cb32_uuid7()`, `mfid.cb32_uuid4()`, and `mfid.uuid_to_cb32()`
  convenience wrappers.
- README and Jupyter notebook of usage examples.
